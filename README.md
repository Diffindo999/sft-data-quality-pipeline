# sft-data-quality-pipeline
> 面向大模型 SFT 微调的合成数据质量管控流水线

## 项目概述
在大模型监督微调（SFT）场景中，低质量、错误、有偏见的样本会污染基座模型，造成模型输出不稳定、幻觉增加。
本项目搭建一套**本地可运行的自动化数据质控链路**，用于合成问答数据的生成、打分、过滤与效果评估。
适合 AI 数据、LLM 数据治理、数据安全方向实习作品集。

### 能力链路
1. **样本生成**：批量构造领域 SFT 问答对
2. **质量质检打分**：设计多维度评分规则，识别坏案例（答案错误、内容简短、逻辑混乱、重复）
3. **自动过滤分流**：将样本分为【合格可直接用于微调】、【待人工复核】两类
4. **量化评估输出**：统计样本通过率、问题分布，输出评估报告

## 目录结构
```
scripts/
├── generate_sft.py   # SFT 合成样本生成模块
├── quality_check.py  # 多维度质量打分模块
├── filter.py         # 样本分流、过滤模块
└── evaluate.py       # 汇总统计，生成质检评估报告
```
## 快速运行
> 前提：Python 环境就绪，按需配置模型 API（本项目支持切换不同大模型服务）
```bash
# 生成 SFT 样本
python scripts/generate_sft.py

# 对样本进行质量打分
python scripts/quality_check.py

# 按分数阈值过滤分流
python scripts/filter.py

# 生成整体评估报告
python scripts/evaluate.py
## 打分策略设计

- 正确性：回答是否贴合问题，无事实错误
- 完整性：回答信息充足，不敷衍
- 规范性：无重复、乱码、无关内容
- 安全性：规避违规、误导类内容
- 可读性：逻辑通顺，结构清晰

根据综合得分划分阈值：

- 高分：直接放行，作为微调训练数据
- 中等：标记，交给人工复审
- 低分：直接丢弃

## 踩坑记录（面试加分点）

1. 对接混元 MaaS API 时，模型 ID、请求体格式校验严格，多次报 400 参数错误，区分了「模型名称」和「服务 ID」的差异
2. 网络超时、接口返回结构不一致，增加返回结果校验逻辑，防止 KeyError 程序崩溃
3. 区分开发产物与源码：运行产出的 json、报告不提交仓库，仓库只保留可复现脚本

## 局限与后续优化方向

- 当前评分策略为规则 + LLM 结合，可接入更专业的 NLP 指标（BLEU、语义相似度）
- 可增加数据去重、隐私识别、内容风险检测模块
- 可以增加可视化面板，更直观展示质检统计结果
- 支持批量导入外部原始数据集，不局限于程序内部生成样本
